`cropStyle` asks for `width: artWidth / pageWidth` — 177.8% for that job. The
theme ships `img { max-width: 100% }`, which clamped it back to 100%. So the
**on-screen proof showed the whole image while the print-ready PDF, drawn on a
canvas where no CSS applies, cropped to the centre 32%.** They approved a proof
that was not what we printed.

  only `{type, list}` crossed to the parent, so an unapproved order was

### Selling work that does not come through a calculator

- `5bbcce9`, `b7f458e`, `89f93d2` — three iterations converging on **quote

Quotes are a non-public CPT `pps_quote`. Orders from them carry
`_pps_qty_tiers`, `_pps_quote_token`, `_pps_requested_date`, `_pps_pay_source`,
`_pps_pay_link`.

**The console password is stored only as a bcrypt hash in
`wp_options['pps_console_key']`.** It is deliberately not written down anywhere
in this repo. Rotating it via the admin screen invalidates every open console
session, because the session cookie is signed with `wp_salt('auth')` *and* the
stored hash. Five failed attempts locks an IP for fifteen minutes.

## 3. Open decisions — nothing is half-built

### QuickBooks API (researched, not started)

Creating QBO payment links without logging in is possible:
`GET /v3/company/{realmId}/invoice/{id}?minorversion=65&include=invoiceLink`
returns a shareable link, and `AllowOnlineCreditCardPayment` / `…ACHPayment`
put a Pay Now button on it — **if QuickBooks Payments is enabled on the
company, which has not been confirmed.** Ask before building.

One interactive OAuth authorization is still required; after that it runs on
refresh tokens (access 1h, refresh ~100 days, rotating). `pps-gdrive.php` is
the same shape and is the pattern to copy.

The bigger prize is **QBO webhooks** — Intuit POSTs on invoice payment with
HMAC-SHA256 signing, which would retire the manual Mark paid button, currently
the weakest joint in the flow. `pps-assistant-webhook.php` is the pattern
(shared secret, `hash_equals`, check inside the handler not `permission_callback`).

**Unresolved:** whether `invoiceLink` expires. Nothing authoritative found, and
`help.developer.intuit.com` is blocked from the sandbox. Design for re-fetch on
demand rather than storing the link at creation.

### Missive (discussed, not started)

A working bridge already exists — `pps-assistant-missive.php` posts to
`/v1/messages` with a Bearer token, `pps-assistant-webhook.php` receives. Config
already holds `missive_token`, `missive_channel_id`, `missive_webhook_secret`.

Two options: a **sidebar iframe integration** (best experience — knows the
conversation, can insert the link into the draft) or a **slash command via rule
+ webhook** (cheaper, reuses the proven pattern, works on mobile).

Three known obstacles for the iframe route:
1. The console cookie is `SameSite=Strict` and **will not be sent in a
   cross-site frame**. Use a signed key in the iframe URL instead.
2. Framing headers must permit Missive's origin. Nothing in the plugin sets
   `X-Frame-Options` on the front end today, but a security plugin would.
3. Missive's JS API specifics are unverified. `pps-assistant-missive.php`
   documents why: *"Missive 403s every automated fetch of its own
   documentation."* Same containment applies — one function, filterable,
   logged, with a visible copy-the-link fallback.

### Proof parity — phase 1 SHIPPED 2026-08-24 (saddle stitch)

The design below is now built for `calc-preview-test.html`: one composition
function (`composePageCanvas`) feeds the proof modal, magnifier, grid,
thumbnails, 3D preview, print PDF and preview JPEGs — screen vs print differ
only in DPI, CSS composes nothing; approval is signed over the SHA-256 of the
print-ready bytes (`_pps_proof_hash` on the order item); the imposition tool
hashes what Drive returns and refuses on mismatch (interactive override flags
output `_UNAPPROVED`, bulk never overrides); flagged preflight checks require
explicit acknowledgment (recorded in the manifest) plus a liability line at
approve. Themed parity tripwire: `tools-parity-saddle.mjs` (pixel-compares the
proof bitmap against the rasterized print PDF; passed at mean diff 0.35/255).

**Remaining:** port the same architecture to the other 7 calculators — their
proofs still composite in CSS (they carry the clamp *exemption* fix, not the
category fix). The saddle port is the template.

## 5. Gotchas earned the hard way

- **The harness must load `pps-theme/assets/css/main.css`.** Every "verified in
  Chromium" claim made without it was against a page production does not serve.
  That is exactly how the clamp survived. `ui/prep.mjs` now injects it.
- **`git apply --3way` can report "applied cleanly" and change nothing.** It did,
  during the imposition reconcile. Always `cmp` the bytes afterwards; never trust
  the exit message.
- **Babel 8 flipped `jsescOption.minimal`.** The compiler now pins
  `minimal: false` explicitly. Without it a rebuild emits non-ASCII characters
  literally (`—`) where every published calculator has them escaped
  (`\u2014`) — runtime-identical, but it buries a one-line diff under thousands
  of cosmetic ones.
- **A colour token can be right on one surface and wrong on another.** Darkening
  the faint ink fixed the light panels and broke the dark ones; three tokens now
  follow the *surface* or the *theme*, whichever actually governs.
- **The publish branch moves under you.** Another session pushed imposition v1.6,
  v1.7 and v1.8 during this window. Always fetch and diff before publishing, and
  check whether the incoming change is also in source.
- **Verify against the shipped bytes, not a retyped copy.** The console and quote
  logic were tested by extracting the real functions out of the deployed file and
  running them against stubs — 40 assertions across the two.
