## What was built on 2026-08-15, and why

All tested by **`php tools-test-seo.php`** — 64 assertions, no WordPress
required. Run it before and after any change to these files.

### `pps-catalog.php` — the primitive

Answers "which products do the calculators own?", which nothing could do
before. The registry's ID string had been re-parsed inline in three places with
each copy disagreeing about duplicates and zeros; `pps_registry_product_ids()`
now lives in `pps-calculators.php` (core, because three core call sites need it
and this file is `file_exists`-guarded) and all three delegate to it.

### `pps-product-feed.php` — `/pps-product-feed.xml`

Scheduled-fetch XML, not the Content API: no OAuth, no quota, debuggable by
opening the URL. Same endpoint shape as `/pps-presets-sitemap.xml`.

**Two decisions worth not re-litigating:**

- **Google does not drive the calculator to find a price.** It reads the page's
  structured data. So the check is *feed vs. our own Product schema*, and both
  now go through `pps_product_price_facts()` so they cannot contradict each
  other. An earlier build published `$product->get_price()` while the schema
  published `_pps_defaults_price` — different fields, guaranteed mismatch.
- **The feed does not judge the price.** Owner's call, 2026-08-15: *"whatever
  the default price might be … I don't care whether it's high or low; where it
  lands it lands."* Only two things keep a product out, both things Google
  rejects outright: no price, no image. Everything else is a warning on the row.
  Do not re-add gatekeeping.

Also: `g:brand` + `g:mpn` (SKU, falling back to `PPS-<id>`). The first build
sent `identifier_exists=no` beside a brand, which is self-contradictory — that
value asserts no GTIN, no MPN *and* no brand.

### `pps-gbp-sync.php` — daily Business Profile rating refresh

Places API, keyed on `seo.places_api_key` + `seo.place_id`, both empty by
default so the file is inert until configured. Built around one failure mode:
the schema only emits `aggregateRating` when both numbers are non-zero, so a
naive fetch-and-store would strip the rating from every page on a timeout. **A
failed fetch changes nothing** — four tests cover network error, HTTP 403, a
200 with no rating, and no credentials.

Flagged to the owner and unresolved: Google treats `aggregateRating` on
LocalBusiness as reviews *you* collected, so mirroring the Google score carries
a known rich-result risk that automation keeps current rather than removes.

### `tools-min-price.mjs` — measured price floors

Drives the real UI with Playwright to find the cheapest quote each calculator
can produce. **Nothing depends on it** — it feeds "from $X" text only. Verified
on one calculator. Needs `--config` with `pps_get_public_config()` output to be
authoritative; without it, it measures the fallback constants in the HTML.
Output is gitignored — measured floors are pricing figures and the repo is
public.

## The queue, in the order it is worth doing

### 1. Preset URLs may be unable to add to cart — verify first

`pps-calculators.php:4767` omits `productId` on preset renders, deferring a
calc-type → product map to "a follow-up PR" that never landed. Every calculator
posts `fd.append("product_id", PPS.productId)` unguarded, and
`pps_ajax_add_to_cart()` rejects a zero ID with *"Invalid product or price."*

If that reading holds, `/letterhead/`, `/mini-catalog-printing/`,
`/color-booklet-printing/` and `/bulk-booklet-printing/` render a working
calculator and then refuse the sale — three of them added specifically to earn
search traffic.

**Two minutes to check:** open `/bulk-booklet-printing/`, configure anything,
click Add to Order. If it carts, something supplies the ID that a code read
missed and this drops down the list. If it does not, the fastest fix is a Rank
Math redirect from each preset slug to its nearest real product.

Full analysis and three ranked mitigations: `docs/PRODUCT_SPAWNER_SPEC.md` §0.

### 2. The product spawner — specced, not built

`docs/PRODUCT_SPAWNER_SPEC.md`. Creating a PPS product today is eleven steps
across four screens, two of which fail silently (forget `_virtual` and shipping
plugins seize the cart; forget the registry and no calculator renders). The
spec collapses it to one screen: paste a quote link, name it, pick a product to
clone copy and images from.

This is upstream of the feed's *value* — feed coverage equals how many products
have a definite price.
